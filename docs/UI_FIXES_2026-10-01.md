# UI and production-route fixes — 2026-10-01

The review covered public account/discovery pages, clinic and platform forms,
and the existing isolated browser transaction and responsive-route suites.

## Fixed issues

- Opening `/account` directly in the deployed Spring application returned 401.
  The shared account route now serves the application shell anonymously, including
  signup query parameters. Account APIs retain their existing authorization.
- Unknown browser page URLs returned an authentication error instead of the
  application Not Found page. An HTML-navigation resource fallback now serves
  the existing shell. API, actuator, webhook and missing-asset requests do not
  receive that fallback; integration tests cover those boundaries.
- `/business` was serving a prerendered client redirect document. It now returns
  an HTTP 308 to `/dentists`, consistent with the existing shared landing route.
- Doctor edit/delete, clinic appointment rescheduling/cancellation/details, and
  owner-credential overlays now use native modal dialogs with shared lifecycle
  handling. Background controls are inert; focus stays inside the dialog and
  returns to the opener. Dismissible dialogs support Escape and backdrop clicks.
  Owner credentials still require explicit acknowledgement before dismissal.
- Doctor deletion failures are visible inside the confirmation dialog, and stale
  errors are cleared before opening it.
- Opening-hours removal is visible on touch screens and keyboard focus rather
  than only on hover. Opening-hour, biography and plan-feature controls have
  contextual accessible names; icon removal buttons use shared touch targets.

## Validation

- Lint and production build, including 28 prerendered routes, passed.
- All 184 frontend tests passed, including four new native-dialog regression tests.
- Backend verification passed: 128 tests passed, one opt-in production-database
  test skipped. Real HTTP tests exercise account navigation, directory redirects,
  unknown-page fallback and protected/resource exclusions against disposable
  PostgreSQL.
- Release-check tests and compiled-asset checks passed. Release smoke checks now
  include shared account pages and verify the directory redirect destination.
- The production-built frontend served by Spring passed the existing isolated
  browser transactions and 192 route/layout checks at 1440, 768 and 320 pixels.
- Supplementary checks found no automated WCAG violations on 26 public, clinic
  and platform page/viewport combinations after entrance animations settled.
  Real browser checks verified modal Tab/Shift+Tab containment, Escape, focus
  restoration and a visible deletion-failure message, plus visible 44px-or-larger
  opening-hours removal controls.

Local screenshots and supplementary accessibility/keyboard logs are under
`/workspace/cloud-setup/ui-review`. Browser fixtures use a separate disposable
database; no production accounts or data were used for these checks. These checks
do not certify every interaction or real payment, email and video integrations.
